# Mercata — Agent Instructions

Read `CONSTITUTION.md` before editing this public repository.

## Publication
- Never disclose private chats, private venting or tone, internal instructions, unpublished documents or research, credentials, private paths, personal identifiers, logs, or any indirect or paraphrased disclosure in any public artifact.
- Write plain, precise English about independently supportable public facts. Do not reproduce language or details from nonpublic discussions.
- Inspect code, comments, examples, filenames, metadata, issue bodies, commit messages, histories, and generated files before publishing. Automated scanning does not prove safety.
- Honor public source terms and provenance; exclude doubtful material.

## Independence and authority
- Work directly on `main` unless explicitly instructed otherwise. Do not create PR branches by default.
- This repository contains its own ontology, gallery, data, scripts and website and requires no private project or service.
- Never edit the Tarium hub registry or claim registration without a separate explicit authorization naming Mercata. Taria is private; Tarium is public. Do not conflate them.
- Do not add marketplace names as specimen records or open research queues without an explicit intake instruction. Documentation examples are not authorization.

## Research
- On authorized admission, generate a stable slug, empty dossier, gallery record, unique OKLab color and all core and relevant specialist tasks.
- Keep ontology machine and human versions aligned; use the specimen schema. Maintain truthful empty state.
- Every research assertion has public source references and dates. Keep unknowns unknown. Track income distributions, zero earners, costs, time, discovery, regulations, ownership and viable experiments without invented conclusions.
- Tasks need acceptance conditions, weights, evidence, and numeric progress. Do not award 100% for unverified work.
- Each specimen's hexadecimal color must remain unique and correspond to stored OKLCH coordinates. Never silently recolor existing specimens.

## Website and verification
- Appearance selector sits at the top right and provides System / Light / Dark, with System default.
- Support keyboard navigation, mobile screens and accessible chart/progress labels.
- Run `node scripts/verify.mjs` and `node --test tests/*.test.mjs`; report missing tests honestly. Avoid unnecessary automated GitHub Actions workflows.
- Keep reporting concise: in-progress milestones with emoji labels, percentages and visual bars. Once bootstrapping is finished, stop rather than admitting unapproved specimens.


## Aggregate social-audience research
- For any platform carrying the `social_audience` profile, use `pipeline/social.json` in addition to core and domain research queues. Do not equate platform use, ad reach, views, creators or community membership.
- Use `ontology/audience.schema.json` and populate demographic and subculture estimates only with attributable, dated, legitimately obtained aggregate sources and explicit denominators.
- Age, sex, gender, ethnicity and political affiliation are not reliably inferable from individual profiles. Do not collect or infer sensitive attributes of individuals. Political content analysis remains descriptive, not demographic-targeted persuasion.
- Separate child-directed animation from general animation. Respect child-audience data restrictions and never profile children.
- Preserve overlapping subculture membership rather than adding overlapping populations. Where evidence is missing, say so.
